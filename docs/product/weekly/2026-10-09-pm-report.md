## Top 3 specs

### 1. Relist inventory + zero-live-listings guardrail

- **Problem / who:** All 8 listings are paused; guests see an empty catalog; no alert fired because no alert kind covers "zero live". Affects guest, host, admin.
- **User story:** As the founder I want to be told within a day if no listing is bookable, so that a pause never goes unnoticed.
- **Solution:** (a) Founder/ops decide which paused listings return and unpause via `/admin/experiences` (data action, not code). (b) New admin alert kind `no_live_listings` raised by the hourly maintenance cron when live count = 0 for more than 24 h, delivered through the existing `notifyAdmin()` rails. (c) Add a pause reason (short text + paused_at/by) captured when pausing in admin and host flows. (d) Catalog empty state copy (see spec 3).
- **Acceptance criteria:**
  - [ ] Cron creates one unacknowledged `no_live_listings` alert after 24 h of zero live and does not duplicate while one is open.
  - [ ] Alert appears in admin alerts inbox and email/WhatsApp rails.
  - [ ] Pausing from admin or host UI requires a reason; stored and shown on the listing.
  - [ ] Unit tests for the cron rule and the action schema (zod); `pnpm scan` green.
- **Arabic/RTL/Saudi:** Reason and alert copy in both locales in `messages/*.json`; Arabic first; no host names in alerts.
- **Metric:** Live listings ≥ N (founder sets N); time-to-detection of zero-live ≤ 24 h. Measure via `experiences` count and `admin_alerts`.
- **Files:** `db/schema.ts` (+ `pnpm db:generate`), `ADMIN_ALERT_KINDS`, the maintenance cron route, `features/admin/experiences/*`, `features/host-experiences/actions.ts`, `messages/{en,ar}.json`.
- **Risks / open:** Why were they paused (Decision 1)? A new column needs `pnpm db:preflight` before deploy.

### 2. Host pipeline: verified → first live listing

- **Problem / who:** 4 verified hosts, 0 with a live listing; 2 applications pending, 1 draft untouched since 2026-08-15. Affects hosts and admin.
- **User story:** As a newly verified host I want a clear next step and a fast review so that my first experience goes live.
- **Solution:** Admin queue shows age and breach state for `host_applications.status='pending'` and `experiences.status='pending_review'` (SLA e.g. 48 h, founder to set); a WhatsApp/email nudge to hosts with a verified status, no listing after 3 days, with a deep link to the listing form; a host dashboard "next step" card in `features/host-dashboard`.
- **Acceptance criteria:**
  - [ ] Admin dashboard lists pending applications and reviews with age; those past SLA are highlighted.
  - [ ] One nudge per host per stage, opt-out respected (`notify_whatsapp`, `notify_email` flags).
  - [ ] Next-step card visible only to verified hosts without a live listing.
  - [ ] Tests cover nudge dedupe and SLA computation.
- **Arabic/RTL/Saudi:** Warm, respectful host tone; WhatsApp approved templates synced via `pnpm whatsapp:templates`; message timing outside prayer/late-night hours (Riyadh time).
- **Metric:** Host activation (verified hosts with ≥1 live listing ÷ verified hosts) from 0% to ≥50% in 4 weeks; median days application→live.
- **Files:** `features/admin/hosts/*`, `features/admin/experience-moderation/*`, `features/host-dashboard/*`, `features/notifications/*`, maintenance cron, `messages/*`.
- **Risks / open:** WhatsApp template approval lead time; small N (4 hosts) makes the metric noisy.

### 3. Demand capture on an empty or thin catalog

- **Problem / who:** Searches rose to 67 (prev 10) and experience views to 157 while no listing is live. Guests leave with nothing. Affects guests and growth.
- **User story:** As a visitor to Abha experiences I want to leave my WhatsApp or email to be told when something is available, so that I do not have to check back.
- **Solution:** When catalog or search returns zero results, show a calm "Opening soon in Aseer" state with a single opt-in form (phone or email, consent line, optional category interest). Server action with zod schema, `useActionState`, stored in a new `waitlist_signups` table; admin can export counts by category. No automatic mass messaging in this change.
- **Acceptance criteria:**
  - [ ] Empty catalog and zero-result search render the state in en and ar with correct RTL.
  - [ ] Submission validates Saudi mobile format (+966) or email, requires explicit consent, echoes `values` on failure, never throws.
  - [ ] Duplicate signup is idempotent; rate limited.
  - [ ] Funnel events `waitlist_view` / `waitlist_signup` recorded in `analytics_events`.
- **Arabic/RTL/Saudi:** Arabic-first copy, no discount language (brand: restraint); phone-first (WhatsApp is the dominant channel); PDPL-aligned consent wording and a deletion route; no family or gender data collected.
- **Metric:** Signup rate = signups ÷ empty-state views; target ≥ 5%. Measure from `analytics_events`.
- **Files:** `app/[locale]/(site)/experiences/*` empty states, new `features/waitlist/*`, `db/schema.ts` + migration, `messages/*`, admin analytics query.
- **Risks / open:** PDPL retention period (Decision 2); becomes moot for a period once inventory returns, but still serves thin categories.
